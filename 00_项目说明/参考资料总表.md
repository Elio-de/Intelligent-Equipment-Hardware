## 8. 开源硬件项目

### 8.1 评估方法

不看 Star 数，按以下 7 项检查：

1. **许可证**：是否明确（MIT/Apache/CERN-OHL/CC-BY-SA），是否允许商用/修改。
2. **硬件完整性**：原理图、PCB 源文件、BOM、Gerber、装配图是否齐全。
3. **文档**：是否有 bring-up、测试记录、已知问题、版本说明。
4. **可维护性**：最近提交、issue 响应、是否依赖停产物料。
5. **设计质量**：保护、去耦、接地、热设计是否经得起检查。
6. **安全性**：电压/电流/电池/机械风险是否适合学习者。
7. **可复用性**：能否抽出某个模块用于教学，而不是只能整机照抄。

### 8.3 本轮的实际检查结论

- **可确认**：moteus 与 ODrive 的许可证分别为 Apache-2.0 与 MIT；仓库以 C++ 为主；镜像页显示数千次提交，说明有持续维护；两者都面向 BLDC/伺服控制，适合作为第 07 章的“真实工程参考”，但不适合初学者整机照抄。
- **未能确认**：由于 GitHub 直连受限，本轮未能逐文件核对 `hw/` 目录、KiCad 版本、BOM 完整性、测试记录。上述“可复用点”来自项目定位与公开资料，正文引用前必须补齐文件级核查。
- **使用建议**：把 moteus/ODrive 当作“设计对照”，用于回答“别人怎么处理电流采样/栅极驱动/编码器/CAN”，而不是当作教学板。第 07 章只抽取模块级思路，不复制整板。
- **风险**：这些项目涉及 24–60 V、数十安培的功率级，绝不适合作为初学者首次上电对象；只能在低压、限流、隔离条件下做信号级验证。

## 10. 资料质量评估方法

| 维度 | 高 | 中 | 低 |
|---|---|---|---|
| 权威性 | 原厂/标准组织/经典教材 | 大学课程/知名社区 | 匿名博客/二手转载 |
| 时效性 | 近 3 年且仍在维护 | 3–8 年 | >8 年或器件停产 |
| 可验证性 | 有测试条件、波形、版本 | 有原理但缺数据 | 只有结论 |
| 适用性 | 与目标器件/场景一致 | 需改造 | 场景差异大 |
| 独立性 | 无商业倾向 | 有厂商倾向但标注 | 软文/带货 |

使用原则：

1. 关键设计结论至少两个独立来源。
2. 厂商文档优先看“测试条件”和“限制”，不只看 Typical Application。
3. 社区答案只用于找线索，最终回到 Datasheet/实测。
4. 任何链接在引用时记录访问日期；失效链接不删除，标注“已失效”。

## 12. 引用格式

正文引用统一使用：

```markdown
[REF-A01] Analog Devices. *Linear Circuit Design Handbook*. 2008. https://www.analog.com/...
```

规则：

1. 先编号，后机构，再标题（斜体），最后版本与链接。
2. 网页资料必须带访问日期：`（访问 2026-11-13）`。
3. 标准引用格式：`IEC 61000-4-2:2018`（年份以实际版本为准）。
4. 开源项目引用：`作者/组织. 项目名. 许可证. 链接（commit/tag）`。
5. 不引用无法追溯来源的截图、网盘资料、二手翻译。
